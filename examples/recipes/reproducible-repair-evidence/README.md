# Recipe: reproducible-repair-evidence

## What this demonstrates

Packaging caller-owned repair records as an offline Evidence v2 directory with the current public `agent-inspect/advanced` APIs.

The recipe writes a failed synthetic trace, `reproduction.json`, `task.txt`, visible-check output, candidate `repair.patch`, `oracle-result.json`, and review `summary.md`; hashes their exact bytes with `buildEvidenceManifest`; verifies the directory with `verifyEvidenceDirectory`; then temporarily tampers with `reproduction.json` to prove that verification reports a hash mismatch. It restores the original bytes before exiting.

For maintainer support bundles that need a reviewed shareable package, see also [Safe support reproduction](../../../docs/SUPPORT-REPRODUCTION.md).

## Why this matters

A failed repair is easier to investigate when the checkout identity, sandbox limits, visible check, candidate patch, and oracle outcome travel together instead of being reconstructed from terminal history. The owning repair tool defines those records; AgentInspect packages and integrity-checks them without requiring a new Evidence field or format version.

## How to run

From the repository root:

```bash
pnpm build
pnpm --filter agent-inspect-recipe-reproducible-repair-evidence start
```

The output remains local under:

```text
examples/recipes/reproducible-repair-evidence/.agent-inspect/evidence/reproducible-repair-evidence/
```

No API key, model call, credential, or network access is required.

## Packaged files

| File | Caller-owned meaning |
|---|---|
| `failed-trace.jsonl` | Failed synthetic repair trajectory using the current persisted trace schema |
| `reproduction.json` | Synthetic target identity, dirty state, digests, names-only env allowlist, exact validation invocation, and repair budget (`reproductionEnvelopeVersion: "0.1"`) |
| `task.txt` | Exact task bytes presented to the repair agent |
| `repair.patch` | Exact candidate patch bytes; a real patch may contain sensitive repository content |
| `check-output.txt` | Synthetic output from the caller-recorded visible check |
| `oracle-result.json` | Synthetic pass/fail + check ids disclosed by the caller, not the hidden oracle implementation |
| `summary.md` | Human-readable outcome and apply/no-apply decision |
| `evidence.json` | Evidence v2 manifest generated by AgentInspect; it is not self-hashed |

`source.sourceHashes` records the SHA-256 of the exact failed-trace input, associated with the repair run id. `files[]` independently hashes the trace and every caller-owned repair artifact. The reproduction record also contains the candidate patch digest and `task.txt` digest so the repair runner's own relationship between those files is explicit.

## Integrity boundary

Evidence v2 proves that the packaged file bytes still match `evidence.json`. The same run id at a different git revision is a different package unless those bytes are identical. It does **not** prove:

- that the repository checkout matched the recorded commit or tree digest
- that the container image or repair runner was trustworthy
- that a hidden oracle was authentic, actually withheld from the repair agent, or executed as recorded
- that the patch is correct or safe to apply
- the identity of the person or system that created the package

AgentInspect does not sign this directory and this recipe is not a replay engine. A real repair runner remains responsible for truthful capture, sandboxing, oracle isolation, redaction, and review before sharing. Exact patch bytes must be treated as potentially sensitive. Manifest `SAFE WITH WARNINGS` here means synthetic caller-owned records still need human review — not that the package is certified share-safe.
